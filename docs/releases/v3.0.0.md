# MCBedrock-LegacyWindows v3.0.0

`v3.0.0` 是本项目从“单客户端分别发布”迁移到“项目级统一 Release”后的首个正式版本。

本次正式版重点整理 **Windows 8.1 x64**：基岩互通版与 Java 经典版启动器中的基岩版统一使用 **Universal Bridge Core 0.4.3**，支持同机注册与共存；同时重新整理面向普通用户的 Release 包目录，根目录改用中文入口，并补充 360 安全软件的实测兼容说明与安装报错提示。

## Windows 8.1 x64

本 Release 提供两个附件：

```text
Win81_BedrockInterop_v2.1.1_Core0.4.3.zip
Win81_JavaClassic_v1.0.1_Core0.4.3.zip
```

两个附件共用同一套 Universal Bridge Core 0.4.3，但客户端包版本独立维护。

### 基岩互通版 v2.1.1

已验证功能：

- 可通过发烧游戏（FeverGames）正常启动；
- 扫码、手机号、邮箱登录流程保留；
- 可进入游戏和世界；
- 使用 `Mode = bedrock-interop`；
- 使用私有 Windows 8.1 ApiSet v4 映射；
- 自动处理 `WinPixEventRuntime.dll` / `W81KERN.dll` 兼容；
- 可与 Java Classic 方案同时安装并共存；
- 不绑定固定 `Minecraft.Windows.exe` 文件大小或 SHA-256。

观察项：关闭游戏窗口后，`Minecraft.Windows.exe` 有时会继续进行一段时间的退出收尾与磁盘 I/O；当前实测等待后会自行正常退出，因此不进行自动强制结束处理。

### Java 经典版启动器中的基岩版 v1.0.1

已验证功能：

- `Minecraft.Windows.exe 1.21.120.0`；
- 可从 Java 经典版启动器正常启动；
- 可进入游戏主界面和世界；
- 单人存档正常；
- 非局域网联机正常；
- 使用 `Mode = java-classic`；
- 可与基岩互通版同时安装并共存。

已知限制：

- 本地 / 局域网联机目前不可用；本正式版暂不继续修改这一部分，以优先保持已经验证正常的启动、单人和非局域网联机功能。

## 安装

1. 关闭正在运行的 Minecraft；
2. 下载与自己客户端对应的附件；
3. 将压缩包**完整解压到 `Minecraft.Windows.exe` 所在目录**；
4. 运行 `安装兼容方案.cmd`；
5. 安装完成后仍从原来的官方/平台启动器正常启动游戏。

安装完成后可运行 `检查兼容状态.cmd`。如果同一台机器同时使用两个客户端，正常情况下可看到类似：

```text
[bedrock-interop] ...\Minecraft.Windows.exe
[java-classic] ...\Minecraft.Windows.exe
```

## 360 安全软件兼容说明

Universal Bridge 需要写入 Windows 的 IFEO `Debugger`：

```text
HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\Minecraft.Windows.exe\Debugger
```

360 会把这一行为识别为“修改映像劫持”。经过实测：

- 360 **自我保护开启**时，安装器可能在写入 `Debugger` 时提示“拒绝访问 / 尝试执行未经授权的操作”；
- 仅退出 360 主界面不能解除这一拦截；
- 暂时关闭 360 的**自我保护**后，可以继续安装；
- 360 提示“有程序正在修改映像劫持”时，确认操作来自本项目后选择**允许**，即可完成安装；
- **安装完成后可以重新开启 360 自我保护，已实测不影响后续正常运行**；
- 启动游戏时如果 360 仍提示 `Win81UniversalBridge.exe` / Minecraft 正在进行“可疑操作”，确认路径正确后选择**允许**即可继续启动。

因此正常情况下不需要卸载 360。正式版安装器在 IFEO `Debugger` 写入被拒绝时，也会给出针对 360 自我保护的明确提示。

建议核对共享 Bridge 路径：

```text
C:\ProgramData\MCBedrock-LegacyWindows\Win81UniversalBridge\Win81UniversalBridge.exe
```

## 从旧版本升级

以前已经使用本项目 Windows 8.1 Bridge 的用户，通常**不需要先运行旧版卸载器**。关闭所有 Minecraft 后，完整解压对应的新附件并运行新的 `安装兼容方案.cmd` 即可。

当前安装器可以识别并迁移本项目已知的旧 IFEO Bridge：

```text
Win81MinecraftBridge.exe
Win81JavaClassicBridge.exe
Win81UniversalBridge.exe
```

具体情况：

- **基岩互通版历史 v2.0.1 → v2.1.1**：可以直接安装新版，无需为了升级而先恢复 WinPix；
- **基岩互通版 v2.0.1 用户现在新增 Java Classic**：可直接先安装 Java Classic 正式包；如果之后不再使用原互通版，做到这里即可；
- 如果希望 **基岩互通版 + Java Classic 两边都继续使用**，需要在两个 `Minecraft.Windows.exe` 所在目录分别运行一次各自正式包的 `安装兼容方案.cmd`；
- **Java Classic 旧独立 RC**：可以直接安装正式包并迁移到共享 Universal Bridge；
- **Universal Bridge 0.4.x 测试版**：可以直接升级；旧 `Mode = interop` 仍可被 Core 0.4.3 识别，重新安装互通版后会写成正式 `Mode = bedrock-interop`；
- 如果曾参与很早期的手工 ApiSet DLL 测试，请先删除当时手动放入游戏目录的 `api-ms-win-*` 测试 DLL。

升级完成后如需卸载，请使用**当前正式包**里的 `卸载兼容方案.cmd`，不要再运行旧版卸载脚本。

## 自定义安装路径

本方案按当前 `Minecraft.Windows.exe` 的**完整路径**注册和分流，代码不依赖发烧游戏的默认安装目录，因此设计上支持其它盘符和自定义文件夹。

目前尚未把“更换盘符 / 含空格目录 / 中文目录”作为独立项目完成实机验证，因此正式版不将这些路径情况标为已验证。如果安装兼容方案后又移动了游戏位置，需要在新的 `Minecraft.Windows.exe` 所在目录重新运行 `安装兼容方案.cmd`。

## Universal Bridge Core 0.4.3

两种客户端共用：

```text
C:\ProgramData\MCBedrock-LegacyWindows\Win81UniversalBridge\Win81UniversalBridge.exe
```

Bridge 根据被启动的 `Minecraft.Windows.exe` **完整路径**分流：

```text
Minecraft.Windows.exe
        ↓
Universal IFEO Bridge
        ↓
按完整路径查注册目标
        ├─ java-classic     → 私有 Windows 8.1 ApiSet v4
        ├─ bedrock-interop  → ApiSet v4 + WinPix/W81KERN
        └─ 未注册路径       → 透明转发
```

卸载某一个客户端时只注销该完整路径；只要还有其它客户端注册，共享 IFEO 会继续保留。只有最后一个目标也注销后，才移除本项目设置的 Universal IFEO Debugger。

## Windows 7

本次 `v3.0.0` 不重新打包 Windows 7 游戏运行方案。现有文档中的实测方案继续有效：

- Java Classic 基岩版：VxKex / VxKex NEXT + `XINPUT1_3.dll`；
- 基岩互通版：VxKex / VxKex NEXT + `XINPUT1_3.dll`；
- 开发者版本：VxKex + `XINPUT1_3.dll` + 禁用游戏目录自带 `dbghelp.dll`。

发烧游戏平台在 Windows 7 上的**下载链兼容**继续由独立项目 `FeverGames-LegacyWindows-Downloader` 维护，不重复打包到本 Release。
