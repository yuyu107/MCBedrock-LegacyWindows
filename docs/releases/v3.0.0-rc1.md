# MCBedrock-LegacyWindows v3.0.0-RC1

> 状态：计划作为 GitHub **Pre-release** 发布。

这是项目从“单客户端分别发布”迁移到“多客户端、多系统统一 Release”后的第一个候选版本。

本次 Release 主要更新 **Windows 8.1 x64** 方案：基岩互通版与 Java 经典版启动器中的基岩版现在共用 **Universal Bridge Core 0.4.3**，可以在同一台机器上同时注册，不再需要切换机器级 `Minecraft.Windows.exe` IFEO Debugger。

## Windows 8.1 x64

### 基岩互通版

附件：

```text
Win81_BedrockInterop_v2.1.0-RC1_Core0.4.3.zip
```

已实机验证：

- 可通过发烧游戏（FeverGames）启动器正常启动；
- 扫码、手机号、邮箱登录流程保留；
- 可进入游戏和世界；
- 使用 `Mode = bedrock-interop`；
- 使用私有 Windows 8.1 ApiSet v4 映射；
- 自动处理 `WinPixEventRuntime.dll` / `W81KERN.dll` 兼容；
- 可与 Java Classic 方案同时安装并共存。

安装路径说明：本方案按当前 `Minecraft.Windows.exe` 的**完整路径**注册和分流，不依赖发烧游戏的固定默认安装目录，因此设计上支持其它盘符和自定义文件夹。当前尚未专门完成“更换盘符 / 含空格目录 / 中文目录”的独立实机验证，因此本 RC 不把自定义安装路径列为已验证项目。如果安装后又移动了游戏位置，请在新的 `Minecraft.Windows.exe` 所在目录重新运行 `install_bridge.cmd`。

观察项：关闭游戏窗口后，`Minecraft.Windows.exe` 有时会继续进行一段时间的退出收尾和磁盘 I/O；当前实测等待后会自行正常退出，因此暂不进行自动强制结束处理。

## 从旧版升级

如果以前已经使用过本项目的 Windows 8.1 Bridge，通常**不需要先运行旧版卸载器**。请先关闭所有 Minecraft 实例，然后把对应的新附件完整解压到当前 `Minecraft.Windows.exe` 所在目录，并运行新包中的 `install_bridge.cmd`。

当前安装器可识别并迁移本项目已知的旧 IFEO Bridge，包括：

```text
Win81MinecraftBridge.exe
Win81JavaClassicBridge.exe
Win81UniversalBridge.exe
```

具体情况：

- 基岩互通版历史 `v2.0.1`：可直接安装新附件，安装器会把旧独立 Bridge IFEO 迁移到共享 Universal Bridge；无需为了升级而先恢复 WinPix。
- Java Classic 旧独立 RC：可直接安装新附件，旧 `Win81JavaClassicBridge.exe` IFEO 会被迁移。
- Universal Bridge 0.4.x 共存测试版：可直接升级；旧 `Mode = interop` 仍可被 Core 0.4.3 识别，并在重新安装基岩互通版附件后写成正式的 `Mode = bedrock-interop`。
- 如果同一台机器同时使用基岩互通版和 Java Classic，建议在**两个游戏目录分别运行一次**各自新包的 `install_bridge.cmd`，使两个注册目标都更新到当前状态。
- 如果曾参与过更早的手工 ApiSet DLL 测试，请先删除当时手动放入游戏目录的 `api-ms-win-*` 测试 DLL，再使用当前方案。

升级成功后建议运行 `check_bridge.cmd`。正常情况下应看到 Universal Bridge Core `0.4.3`，以及当前机器实际安装的目标，例如：

```text
[bedrock-interop] ...\Minecraft.Windows.exe
[java-classic] ...\Minecraft.Windows.exe
```

旧版 Bridge 文件即使仍留在游戏目录中也不会继续作为当前 IFEO 使用；确认新方案启动和进入世界正常后，可以再整理旧测试文件。升级完成后如需卸载，请使用**当前新包**中的 `uninstall_bridge.cmd`，不要再运行旧版卸载脚本。

## Universal Bridge Core 0.4.3

两种客户端现在共享：

```text
C:\ProgramData\MCBedrock-LegacyWindows\Win81UniversalBridge\Win81UniversalBridge.exe
```

Bridge 根据被启动的 `Minecraft.Windows.exe` **完整路径**读取注册模式：

```text
java-classic
bedrock-interop
```

早期共存测试使用过：

```text
interop
```

Core 0.4.3 仍兼容该旧值，并按 `bedrock-interop` 处理；重新安装新版附件后会写入正式新模式名。

卸载某一个客户端时只注销该完整路径；只要还有其它客户端注册，共享 IFEO 就继续保留。只有最后一个目标也注销后，才移除本项目的 Universal IFEO。

## Windows 7

本次 `v3.0.0-RC1` 暂不重新打包 Windows 7 游戏运行方案。现有实测结论继续有效：

- Java Classic 基岩版：VxKex / VxKex NEXT + `XINPUT1_3.dll`；
- 基岩互通版：VxKex / VxKex NEXT + `XINPUT1_3.dll`；
- 开发者版本：VxKex + `XINPUT1_3.dll` + 禁用游戏目录自带 `dbghelp.dll`。

发烧游戏平台的 Windows 7 **下载链兼容**继续由独立项目 [FeverGames-LegacyWindows-Downloader](https://github.com/yuyu107/FeverGames-LegacyWindows-Downloader) 维护，不作为本 Release 的附件重复打包。

- FeverGames 自定义安装目录 `D:\FeverGames`；
- 7-Zip 自定义安装目录 `D:\7-Zip`；

- Win7 兼容 `downloadIPC.exe` 替换成功；

下载兼容和游戏运行兼容仍然分开维护：下载器 v1.3.1 解决发烧游戏平台在 Win7 上的新版下载后端问题；下载完成后，`Minecraft.Windows.exe` 仍按上面的 VxKex / `XINPUT1_3.dll` 方案运行。
