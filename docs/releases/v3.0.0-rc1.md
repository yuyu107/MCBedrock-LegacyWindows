# MCBedrock-LegacyWindows v3.0.0-RC1

> 状态：计划作为 GitHub **Pre-release** 发布。

这是项目从“单客户端分别发布”迁移到“多客户端、多系统统一 Release”后的第一个候选版本。

本次 Release 主要更新 **Windows 8.1 x64** 方案：基岩互通版与 Java 经典版启动器中的基岩版现在共用 **Universal Bridge Core 0.4.3**，可以在同一台机器上同时注册，不再需要切换机器级 `Minecraft.Windows.exe` IFEO Debugger。

## Windows 8.1 x64

### 基岩互通版

附件：

```text
Win81_BedrockInterop_v2.1.0-RC1_Core0.4.3.zip
```

已实机验证：

- 可通过发烧游戏（FeverGames）启动器正常启动；
- 扫码、手机号、邮箱登录流程保留；
- 可进入游戏和世界；
- 使用 `Mode = bedrock-interop`；
- 使用私有 Windows 8.1 ApiSet v4 映射；
- 自动处理 `WinPixEventRuntime.dll` / `W81KERN.dll` 兼容；
- 可与 Java Classic 方案同时安装并共存。

观察项：关闭游戏窗口后，`Minecraft.Windows.exe` 有时会继续进行一段时间的退出收尾和磁盘 I/O；当前实测等待后会自行正常退出，因此暂不进行自动强制结束处理。

### Java 经典版启动器中的基岩版

附件：

```text
Win81_JavaClassic_v1.0.0-RC2_Core0.4.3.zip
```

已实机验证：

- `Minecraft.Windows.exe 1.21.120.0`；
- 可从 Java 经典版启动器正常启动；
- 可进入游戏主界面和世界；
- 单人正常；
- 非局域网联机正常；
- 使用 `Mode = java-classic`；
- 可与基岩互通版方案同时安装并共存。

已知限制：

- 本地 / 局域网联机目前不可用；此 RC 暂不继续修改该部分，以优先保持已验证正常的启动、单人和非局域网联机功能。

## Universal Bridge Core 0.4.3

两种客户端现在共享：

```text
C:\ProgramData\MCBedrock-LegacyWindows\Win81UniversalBridge\Win81UniversalBridge.exe
```

Bridge 根据被启动的 `Minecraft.Windows.exe` **完整路径**读取注册模式：

```text
java-classic
bedrock-interop
```

早期共存测试使用过：

```text
interop
```

Core 0.4.3 仍兼容该旧值，并按 `bedrock-interop` 处理；重新安装新版附件后会写入正式新模式名。

卸载某一个客户端时只注销该完整路径；只要还有其它客户端注册，共享 IFEO 就继续保留。只有最后一个目标也注销后，才移除本项目的 Universal IFEO。

## Windows 7

本次 `v3.0.0-RC1` 暂不重新打包 Windows 7 方案。现有实测结论继续有效：

- Java Classic 基岩版：VxKex / VxKex NEXT + `XINPUT1_3.dll`；
- 基岩互通版：VxKex / VxKex NEXT + `XINPUT1_3.dll`；
- 开发者版本：VxKex + `XINPUT1_3.dll` + 禁用游戏目录自带 `dbghelp.dll`。

后续如果 Windows 7、Windows 8.1 开发者版本或其它系统方案有新附件，将直接加入同一个项目级 Release，不再单独按客户端创建 Release。
